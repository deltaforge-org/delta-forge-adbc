## What's Changed

Alignment of the DeltaForge ADBC driver to the 1.2.0 platform release.

- The Arrow-native driver works unchanged against the new compute gateway and the cloud autoscaler pool. It already direct-dials a compute node over the deployment's public endpoint and mirrors the control plane's scheme (http or https) automatically, so a query routed to a freshly warmed cloud slot behaves the same as one against a fixed node, with no driver configuration change.
- Compute-pool routing and client usage attribution are as introduced in 1.0.8: every query carries the `x-deltaforge-node` selector (direct-dial when a node is pinned, server-side load-balancing when it is not), and requests are tagged as ADBC traffic (`X-DeltaForge-Client: adbc`) so DeltaForge's per-table and fleet usage dashboards record when the lake was reached through the ADBC driver.
- Versioned to the 1.2.0 platform release.

Arrow result handling, type mapping, and schema are unchanged from 1.0.8; this is a version-alignment release with no change on the wire.
